## Why

`skills/testing` shipped with a pointer section naming `python` and `langgraph` as where stack-specific testing material belongs, and stated plainly that a skill named there "may currently carry little on testing — that is a fact about its present state, not about its scope." That promissory note is now the gap: an agent that loads `testing` for a Python or LangGraph task is told to load the matching skill before writing tests, and the matching skill has nothing to say.

`skills/python` carries no testing content at all. `skills/langgraph` carries three sentences on `.invoke()`/`.stream()` divergence and nothing else. So the floor states what makes a test's evidence interpretable — the four failure states, the provenance rule, the baseline — and then hands off to skills that cannot say how to express any of it. The division `add-testing-skill` designed only works once both halves exist.

`agents/openspec-test-writer` sharpens the same gap. Its dispatch loads `testing` plus the matching stack skill, and its cold-run check recorded exactly this: the run reported "no skill in this library specifically covers Python's `unittest` runner… proceeded on `testing` + `python` alone," a real observation from a real dispatch rather than a hypothetical.

## What Changes

- Add a **`references/testing.md` to `skills/python`** covering what the `testing` pointer promises for that stack: `pytest` test and fixture structure, fixture scope and the shared-mutable-state trap it creates, parametrisation, what makes an assertion meaningful in Python (bare `assert` and pytest's rewriting, `pytest.raises` scoped narrowly, comparing floats), `conftest.py` layout, and where mocking boundaries sit. `python` already pre-splits into `references/`, so this follows its established shape rather than inflating the always-resident floor.
- Add a **`references/testing.md` to `skills/langgraph`** covering the stack-specific half: **stubbing a tool-calling model** (the fiddly part — a fake that returns plain text is easy, one that emits `tool_calls` to drive a conditional edge through a tool node is not), testing a **node as a plain function** versus testing **routing** versus testing the **compiled graph**, and **checkpointer-backed state across turns**.
- **Expand `skills/langgraph`'s existing `## Testing` floor section** modestly. `langgraph-practice` requires testing guidance in the always-resident floor, so the floor keeps the `.invoke()`/`.stream()` point and gains a **four-level ladder** as a short orienting paragraph — a node's behavior by calling the node; a routing *decision* by calling the path function where the edge is conditional, or the node itself where routing is a `Command(goto=...)` return; that the decision *reaches the intended node*, which does need the compiled graph; and cross-turn behavior, which needs a checkpointer — with the depth routed to the new reference. The distinction between the routing decision and the wiring it depends on is the point: collapsing them pushes a test above the smallest unit that can observe the behavior, which is exactly what the floor this change connects to forbids.
- **Add a pointer line to each skill's `Where to go deeper` section**, since both specs require `SKILL.md` to close with a pointer naming each reference file — a new reference that the floor does not name would violate a requirement both skills already carry.
- **Cross-reference `testing` from both skills**, so the relationship the `testing` skill states one-directionally becomes navigable from either end: a reader who entered through `python` on a test-writing task learns the floor exists.
- **Verify every version-dependent claim live**, per each spec's own requirement — `python-practice` demands verification against a live interpreter and tooling, `langgraph-practice` against the released package. Neither `pytest` nor `langgraph` is currently installed in this environment, so both must be installed before the claims are written, as `add-langgraph-skill` did.

**Runner scope is `pytest` only.** The cold-run observation quoted above named `unittest` specifically, and this change does not add `unittest` coverage — `python-practice`'s consuming-project deference is the route for a project on a different runner, and recording that here keeps it a decision rather than an oversight a later reader has to reconstruct.

Deliberately **not** in this change: testing sections for `bash` or `terraform`, which the `testing` pointer also names and which are the same shape of work but a separate stack and a separate verification burden; and any change to `skills/testing`'s **guidance content**, whose pointer section already anticipates this content arriving. Its recorded trigger fixtures are a separate matter: if the description edits here displace it on a test-writing prompt, `skill-authoring` requires that fixture repaired in this change, and that repair edits `skills/testing/SKILL.md`.

## Capabilities

### New Capabilities
(none)

### Modified Capabilities
- `python-practice`: the structure requirement names `references/testing.md` in its minimum-coverage list, and a new requirement states what that file must cover and holds it to the same verified-before-written discipline the capability already applies to its other version-dependent claims.
- `langgraph-practice`: *Conditional-Edge Routing and Recursion Limits Are Covered* is modified to qualify its compile-vs-execution claim, which this change's floor content would otherwise contradict — a fourth `MODIFIED` requirement added after review established the conflict is created by this change regardless of what verification returns. The existing *Streaming-Mode and Testing Distinctions Are Covered* requirement is extended so the always-resident floor carries the test-level distinction alongside the `.invoke()`/`.stream()` point, and the structure requirement gains testing depth as a required reference topic, with all three reference files named in the requirement body. A new requirement states what that reference must cover, with stubbing a tool-calling model named explicitly as the part that is hard and therefore load-bearing.

## Impact

- **Affected**: new `skills/python/references/testing.md` and `skills/langgraph/references/testing.md`; conditionally `skills/testing/SKILL.md` and `agents/openspec-test-writer.checks.yaml`, if the trigger-check sweep finds a recorded fixture in either falsified by the description edits here; edits to both `SKILL.md` files (the `Where to go deeper` pointer in each, `langgraph`'s `## Testing` **and conditional-edge** sections, and a cross-reference to `testing` in each).
- **First change in this repository to carry `MODIFIED` deltas.** Every prior change has been `ADDED`-only, so the `MODIFIED` path — a delta header that must match an existing requirement exactly, and the full-content rule that a partial `MODIFIED` loses detail at archive time — is exercised here for the first time and is a real risk of this change rather than a routine step.
- **Descriptions are edited, which invalidates recorded trigger checks.** Both skills' descriptions gain testing coverage, and `skill-authoring` makes a description edit invalidate that asset's recorded check. Both skills' fixtures are re-run and updated in this change, not deferred.
- **Verification requires installing two packages.** `pytest` and `langgraph` are absent from this environment. Both specs forbid writing a version-dependent claim that was not verified, so installation is a prerequisite of the writing step rather than an optional convenience; where a live check proves impossible, the claim is sourced from current documentation and recorded as resting on documentation rather than a live check.
- **No new tag, no new asset, no tooling.** Both skills already carry their tags; this change adds files under existing skill directories and edits existing bodies.
